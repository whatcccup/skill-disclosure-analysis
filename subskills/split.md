# 子技能二｜拆分原技能规则

在用户要求“提炼、拆分、迁移原作者方法”时读取。输入是用户指定的原 `SKILL.md` 包，以及已完成且可回链的解释阶段成果（若有）。没有解释报告时，先建立最小来源索引；不为进入本阶段强迫用户重做披露图。此阶段**只分析和提出限定任务族的候选骨架**，不生成派生 `SKILL.md`、不运行原包。

本阶段要让下一位读者知道**怎么学、怎么用**，而非只给分类标签。交付开头用一段导读串起：从来源节点读懂原规则解决的问题 → 判断迁移动作 → 用映射改写为自己的候选规则 → 选定适用任务族并填骨架 → 第三阶段用真实场景和用户决定验证。四类表回答“取舍什么”；规则映射回答“为什么这样改、下一步怎么改”；骨架回答“这些候选规则在某类任务里如何协同”。三者不是三份彼此独立的清单。

## 1. 原子化并分四类

逐条从原文抽取会影响行为的规则；同一段含有方法、作者固定值与人工决定时拆成多条。四类按**迁移动作**判断，而非评价作者好坏：

| 类别 | 判断 | 处理 |
| --- | --- | --- |
| 可直接复用 | 换场景仍成立，且不依赖作者身份、品牌、专用脚本或特定数据 | 用自己的话保留方法与验证门槛；引用原出处 |
| 需要参数化 | 方法成立，但输入类型、字段、阈值、工具、版式或目标环境会变 | 列清参数、由谁决定、缺值时停在哪里；不擅填作者默认值 |
| 不应迁移 | 作者品牌、私密信息、特有视觉资产、局部实现、未经验证的效果保证，或不适用新场景 | 排除并写原因；若确需复制代码或实质文档，另查许可与归属 |
| 必须人工判断 | 会改变事实、法律／专业含义、公开范围、关键选择或终版状态 | 设明确确认节点，写问谁、何时问、未答复能否保留草稿 |

同一规则可以拆成多个**原子项**分别归类；不要把一个完整段落粗暴贴到两类。每项给稳定规则 ID，并回链解释阶段的源节点；映射中仍须单独写明原文档名称和链接，不能只给节点编号。对每个类别写明读者的下一步：可复用项学习其解决的问题和检查效果，再用自己的话试写；参数化项找出哪些值要由自己的场景决定；不迁移项学会识别依赖或失效条件，不照搬；人工判断项明确由谁、在何时决定以及未答复状态。**定位节点只是阅读入口，不等于已经学会或获准照搬。**

## 2. 建立规则映射

每个原子项必须写明七项：**原规则、通用规则、动作、参数、风险、验证方式、证据位置**。动作使用“保留／参数化／排除／设人工确认”；原文没有说明的字段写“无法从文档确认”，不能借其他案例填补。原规则与通用规则分别标注，避免把分析者建议归给作者。风险要说明迁移后会出什么具体错；验证方式应观察实际输入或产物，不只检查规则文字是否出现。

**证据位置必须让人找得到原文。**每个原子项的“证据位置”字段至少写：①原文档的**完整文件名**（含扩展名；同名文件加所在目录）；②一个可打开该文档的 **Markdown 链接**，链接目标用从分析文件到源文件的相对路径，或可用的完整 URL；③文档内定位线索，如原文标题／小节、段落开头、规则编号，或已核对的行号范围。多个来源分别列出，不用“见上文”“S/E/M”“原 Skill”等缩写替代文档名；证据 ID 和披露树节点只能作为附加索引。若能可靠跳到标题、段落或行，就用对应锚点／链接；若环境不支持精确跳转，链接至少打开**正确文件**，并在链接旁写清内部定位线索及“只能跳到文件，不能直达该段”。不得编造未验证的锚点或行号。

推荐格式：`证据位置：[extraction-guide.md](原包/references/extraction-guide.md) → “Step 6 — Triage density” 小节，讨论主干与附注；链接只能打开文件，不能直达该段。` 真实交付中须替换为实际存在的文件名、路径和标题。写完后逐条检查 Markdown 链接能否打开目标文件；精确锚点可用时再检查是否落在目标段落，不能验证就如实标明。

**原规则不能写成口号。**在“原规则”字段中，用自己的话交代原技能处理什么输入、遇到什么判断、做什么动作、得到什么可观察效果；必要时说明前后相邻步骤和失败处理。再用“通用规则”概括可迁移机制，用“动作”写出读者在新任务中保留、替换、排除或询问的具体操作。每张卡最后补一句**读者下一步**：应查哪个源节点、从中学什么、怎样把它带入自己的场景。短摘录与定位链接用于核对，不大量复制原文。

例如“先找主轴再挂分支”不能单独作为映射。对于原技能的图示重绘，应说明：输入若是手绘时间轴，沿轴的点才是主事件，旁注附属于相应事件；若是纯文字案情，则须从日期、行为人、行为等内容重新构造顺序，不能按视觉位置读取。作用是避免把旁注错误提升成独立事件或把诉讼主张误写成事实。迁到案件泳道时间轴时，可以把已核实的日期事件放到左轴对应行，行为人进入右侧泳道，补充说明附在事件详情和来源中；具体泳道顺序、是否合并共同事件仍待用户规则决定。核验应逐项追踪原材料中的主事件与附注。**这是一种有适用条件的结构化方法，不是所有语义提取任务都要寻找“主轴”。**

允许用表格或逐项卡片。跨类重复的源句只在来源索引保留一份，映射行用同一证据 ID 回指。原脚本可静态阅读以核对实现，但不运行。

## 3. 输出限定任务族的候选骨架

先给骨架命名，并写清**适用前提、适用任务、不适用任务**。只对已有证据和用户目标共同支持的任务族提炼**触发、输入、流程、决策、输出、验收、最小示例**；不可用一个场景的骨架冒充所有领域通用流程。区分跨场景可借的检查机制（如来源追踪、存疑标注、人工确认）与仅当前场景成立的步骤（如“新材料对照旧成果”）。骨架必须保留来源质检、人工确认、失败路径与安全边界：指定来源与版本、存疑和冲突、草稿／终版状态、可选步骤失败、实际交付清单、权限与外发边界。骨架是第三阶段改造映射的**输入模板**，不是已安装技能；新场景不符合前提时，回到映射重新选规则，不硬套模板。

最小示例只说明一个输入如何经过判断得到候选输出及人工门槛。优先用虚构或脱敏例，明确它不是原包运行结果。示例不把作者品牌、具体颜色、人物或敏感路径写成通用默认。

## 阶段验收与移交

- 四类均被考虑；某类无项时写“本次未识别”，不要凑数。
- 每个被保留的骨架规则能回溯到映射 ID 和源位置；被排除项不悄然出现在骨架。
- 抽查至少一个完整链条：源段落及上下文 → 原规则的输入、判断、动作、效果 → 迁移取舍 → 新场景动作 → 可观察验收。读者能据此回答“我找到后学什么、接着做什么”。
- 逐项检查“证据位置”含完整文档名、可打开的 Markdown 文件链接和文档内定位线索；跳转精度与实际验证一致，不能用证据 ID、简称或孤立行号代替。
- 骨架写明任务族与不适用条件；最小示例符合该任务族，不把“增量更新”当作纯新建或任意语义提取的通式。
- `无法从文档确认`、待参数和人工决定分别列清。数量对账之后再检查内容是否错分或漏项。
- 交付“规则映射＋通用骨架”及简短缺口，不复制解释阶段的披露树和风险包全文。用户未要求第三阶段时，到此停止。
