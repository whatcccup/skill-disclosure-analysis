# 子技能三｜升级为自己的工作流

仅当用户要求把原技能的某项能力改成自己的版本，或把已提炼的方法重新组合成新工作流时读取。输入是用户的目标、原技能相关文件，以及已有的[拆分阶段](split.md)规则映射／候选骨架（若适用）。**候选骨架不是默认起点，也不是升级的必经层。**先审查，再生成；用户确认具体改造映射之前，不生成派生 `SKILL.md`、脚本、配置或模拟成品。

## 0. 先判定改造范围与起点

| 路线 | 何时选 | 以什么为起点 | 主要交付 |
| --- | --- | --- | --- |
| **局部改造** | 用户保留原技能的一项或一条完整能力，只修改版式、参数、输入／输出等局部规则 | 原 `SKILL.md` 中对应分支及其实际依赖文件、数据合同、脚本；已有披露树和规则映射作索引 | “原能力链 → 保留／替换／删除／新增”影响图与最小改动方案 |
| **工作流重组** | 用户要跨分支组合能力、改变任务目标，或源技能已无法承担新流程 | 来源规则映射与限定任务族的候选骨架；不匹配时从原文重新选规则 | “候选机制 → 我的流程”改造映射与缺口 |

先用用户目标和源包证据判断路线。不能因为拆分阶段已经产出骨架，就强迫局部改造绕行骨架。若用户只要“案件时间轴的输出形态改成左轴＋右侧泳道”，应沿原技能的**时间轴触发 → 来源预检 → 抽取与事实保真 → 时间轴类型判断 → 时间轴数据合同 → 渲染／导出 → 质检与确认**追踪能力链；重点审查版式选择、事件字段、渲染器、样式规则和导出验证之间的依赖。保留仍适用的前序读取、证据、存疑和人工确认规则。若某个原有脚本无法承载新泳道版式，说明替换边界和需要重做的部分，不假装只改一行配色即可完成。

局部改造不要求先写一份覆盖原包全部功能的四类拆分或抽象骨架；只补目标分支涉及的最小来源证据和迁移判断。工作流重组也不把狭窄骨架外的源能力自动视作无用。两条路线都不得直接覆盖原包，除非用户明确授权修改该具体对象和范围。

## 1. 补齐输入合同

按选定路线核对九类输入，并记录来源、已确认值与缺口：**场景、使用者、输入来源及版本、工具权限、交付格式、归档位置、人工确认节点、质量标准、真实测试案例**。还要区分新建、更新或两者，目标软件／链接环境，以及原文件、旧成果和新增材料的范围。局部改造先继承原能力链中仍有效的输入约束，再询问变化所必需的值；工作流重组逐项重定合同。可从用户现有回答与当前项目文件核实，不重复提问；无法证明的决策项只提必要问题，不替用户选择配色、事实含义或公开范围。

## 2. 先交改造映射与缺口清单

每项写：**原规则／源文件位置或候选骨架 ID**、用户规则或偏好、保留／替换／删除／新增动作、受影响的上下游模块、参数、风险、验证方式、证据或用户确认位置。局部改造必须把仍保留的原能力链列清，并逐项标出实际改变的文件／规则与连带影响；工作流重组则以候选机制为索引。不得只列新样式而遗漏数据合同、渲染和验收的相应调整，也不得因为抽象骨架较窄而删掉原分支中仍必需的步骤。把**用户已决定**、**供审阅的提案**、**待用户决定**分开。清单指出哪个缺口会阻止生成、哪个仅阻止实测、哪个可随具体任务确定。只提问真正阻止下一步的内容；等待答复期间可完成不依赖答案的来源核对和方案。

把所选路线、改造映射、影响范围与准备生成的文件清单给用户审阅。只有用户明确确认该方案，才进入下一步；沉默、超时或模型自行写入 `confirmed: true` 都不算确认。用户已在本会话确认过的决定不再重复索要。

## 3. 确认后定制

按已确认范围生成新 `SKILL.md` 和确有用途的参考、脚本或资产。局部改造优先保留被选分支的有效流程与数据保真约束，只替换确认过的环节；工作流重组按新任务合同实现。入口保持简短，按需披露子流程；保留来源质检、人工确认、失败、安全、草稿／终版和实际交付边界。作者的方法可抽象，作者私密信息、品牌、正式资产及未经核实的保证不复制。若复用代码或实质文本，先核对许可条款与归属并保留要求的声明；不得把原作者许可误写成新作品自动获得的许可。

改造映射、缺口清单和演练验收记录按入口的“分析产物位置”规则，默认保存在当前项目文件夹；项目位置不明时先请用户指定目录。**新技能本体**写入用户指定位置；未指定时，按当前平台约定选择可发现的技能目录。分析产物、派生技能、原包与测试输出分开放，避免覆盖旧版或污染来源。只在确认过的工具和数据范围内运行新技能。

## 4. 真实任务桌面演练与验收

至少选一件有授权的真实任务，按“输入版本 → 候选结构 → 人工确认 → 新技能输出 → 回读／打开 → 逐项对照”记录证据。局部改造要重点比较**原分支保留的能力**和**改过的环节**：保真、存疑、来源、确认等旧门槛仍起作用，新版式／格式符合用户要求。新建与更新都在技能范围内时，应分别测；若增量材料尚未提供，标“更新路径待测”，不能用新建结果代替。比对来源、事实、参数、图／文件、链接、确认记录及实际生成清单；失败、跳过和浏览器或桌面工具限制独立列出。脚本退出码、文件存在或静态 XML 成功不能代替目标软件视觉和交互验收。

交付新技能路径、采用的改造映射、测试输入、通过项、未测项、残余风险与下一次需要的材料。用户尚未确认关键事实或视觉排序时，样品维持草稿；不要把课程讲稿、模拟台词或第三方演示当成本次技能运行结果。
