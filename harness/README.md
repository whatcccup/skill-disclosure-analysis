# 三阶段 Harness

本 Harness 检查**阶段路由、证据保真、去重与停止条件**。它不是被分析 Skill 的运行许可，也不能用静态测试冒充真实桌面演练。

## 阶段门槛

| 阶段 | 进入条件 | 主要产物 | 不可越过的门槛 |
| --- | --- | --- | --- |
| 解释 | 用户要求理解原包 | 弹窗选简版或完整；无答复／无法弹窗默认完整报告和图 | 只读原包；图只画工作节点，明确列举的触发条件逐项展开 |
| 拆分 | 用户要求提炼可迁移规则 | 带学习动作的四类取舍、还原原规则上下文的七字段映射、限定任务族的候选骨架 | 不生成派生 Skill；每项证据位置写完整文档名、Markdown 文件链接和内部定位线索，骨架标适用与不适用 |
| 升级审查 | 用户要求局部改造或重组技能 | 局部能力链或候选骨架 → 我的规则，附影响范围与缺口 | 九类输入缺失时只问必要问题；局部改造不强迫套狭窄骨架；未确认不生成 |
| 升级制作 | 用户确认改造映射 | 新 Skill、真实任务验收记录 | 原包只读；未测、失败、跳过分开报告 |

## 去重合同

1. **解释保存观察。**源段落、引用文件、声明／代码／未知由解释阶段记录一次，并给稳定的证据链接或 ID。
2. **拆分保存抽象与学习路径。**映射行引用证据 ID，简述原规则的输入、判断、动作、效果，再写迁移动作、读者下一步和验证；不复制披露树或风险包全文。候选骨架只引用映射 ID，并限定适用任务族。
3. **升级保存用户选择。**局部改造引用原分支规则与文件；工作流重组引用候选骨架 ID。映射只写新场景的保留、替换、参数、影响、缺口与验收。新 Skill 写运行规则，不复制三份分析报告。
4. 同一源句可拆成不同原子规则，但 ID 不重复；作者规则、通用规则、用户规则分栏，不互相冒名。若用户只要后一步，补最小前置证据，不重做完整前序产物。

## 回归场景

[cases.json](cases.json) 给出八个必须人工前向检验的情境：只解释、弹窗无回复、分析目录不明、四类拆分、过度压缩的原规则、时间轴局部改造、输入不足的升级、已确认后的生成和演练。分析文件默认进入当前项目；项目目录不明时先问用户，不回退到技能安装目录。检查点是行为与边界，不是关键词匹配。每次改变路由、门槛或子技能说明时，至少检查受影响场景；涉及全部三阶段的修改应跑全套。

运行 `python3 scripts/run_harness.py` 做自动静态检查：确认解释核心与当前基准一致、阶段文件和回归场景齐全，并在临时目录用微型 Skill 模型调用现有绘图脚本，检查 draw.io／SVG 可解析、四条口令逐项出现、非工作 README／License 被排除。此脚本不运行任何被分析 Skill。**自动通过不能证明弹窗实际出现、模型在真实请求中正确分类、人工确认真实发生，或目标编辑器／桌面软件已打开。**
